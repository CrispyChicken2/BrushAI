## Proposed refinements (for the chef to accept; none is applied silently)

1. **T-024** (eval set): the sources are fixed by the protocol (Met Open Access for the 40 paintings, per-file CC0/PD photographs, 30 SDXL images from the 30 prompts and seeds of evaluation.md section 1.4). Deliverable: a
   manifest with the stratified, seeded draw (`random.Random(22)`), the dev flag, licence strings, retrieval dates and SHA-256 of every image, the fetch script, and the data card in `docs/data_sources.md`. The dev split (10) is fixed in this
   ticket before any method is run. Verify the Smithsonian CC0 statement file by file before using it as a photograph source. The Met API `search` endpoint was retired on 2026-10-01: use v1.1 or the object list.
2. **T-025** (saliency maps): evaluation model **InSPyReNet Swin-B (DUTS-TR)**, control **spectral residual**; the checkpoint hash is pinned and the weights are not redistributed. The M4 plan must exclude InSPyReNet (circularity rule). Measure the saliency model's VRAM (estimated < 3 GB).
3. **T-026** (harness): implements the `Producer`/`PaintResult` interface, the 15-checkpoint grid, AUC@B with the per-image reference, SW-LPIPS with `lambda = 0.1` (and the `0` / `0.3` sensitivity columns), strokes-to-target with right-censoring, the
   paired statistics (Wilcoxon, rank-biserial, bootstrap, Holm), the controls (blank, blur, canvas colour), and `configs/eval/protocol.yaml`. Tests: AUC of known synthetic curves, SW-LPIPS with uniform saliency equals LPIPS, prefix consistency, censoring, Holm on
   known p-values, determinism. LPIPS-VGG runs in chunks of at most 2 canvases.
4. **T-027** (renderer speed-up): downgrade from "makes the baseline affordable" to "speeds up the fixed-budget side check and the M4 grid"; the prefix protocol is affordable without it (47 h). It is not on the M3 critical path.
5. **T-028/T-029/T-030** (Learning to Paint): data policy and check strategy as in evaluation.md section 8 (Met CC0 subset of 100,000 images disjoint from dev/test by object and artist; tolerance of 25 % against the released actor, to be confirmed in T-030 before the run;
   no claim of reproduced LPIPS). T-029 should measure the cost of one run first; the number of training seeds then follows the 48-hour rule of section 6.
6. **T-031** (PT-init + refinement): one more method row in the same protocol (prefix of the refined sequence; the strokes count above 2000 only matters through the prefix); the refinement hyper-parameters are tuned on the dev split only.
7. **T-032** (full run): test split once after code freeze; every run logged; the table set is B1 final metrics at 4 budgets, B2 AUC@B, B3 SW-LPIPS, B4 strokes-to-target, B5 runtime and VRAM, plus the anytime-curve figure and the failure gallery (the five test images with the largest
   paired LPIPS gap per method). The fixed-budget side check of the optimization baseline (30 test images x 3 seeds) is included, with its cost (about 54 h) planned.
8. **T-033** (gate): audit like M1 and M2 (fresh clone, one-command regeneration of the tables from stored data, protocol vs execution diff: any deviation from evaluation.md must be an entry in its Amendments section).

## Success criteria (as refined)
Unchanged from the plan, plus: the protocol is fixed in writing before any run (done by T-022, changes only through its Amendments); the dev/test split is fixed and no dev image appears in a table; the circularity rule is checked (the M4 saliency models differ from the evaluation model);
every claim of a difference carries a test, an effect size and an interval; a method that cannot reach a budget is shown as such.
