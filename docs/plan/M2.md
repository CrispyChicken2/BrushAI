# Milestone M2: Paint Transformer reimplementation and reproduction of the paper results

Milestone M2 delivers a reimplementation of Paint Transformer (Liu et al., ICCV 2021) trained self-supervised on synthetic strokes, a multi-scale
inference pipeline, and a reproduction of the paper results with every gap quantified and explained.

## Plan (as given)

Milestone M2 — Paint Transformer reimplementation + reproduction of paper results.
Tickets: T-010 study note · T-011 PT-compatible rendering + synthetic stroke data generator · T-012 model + Hungarian losses ·
T-013 training pipeline (bf16, resume, logging, validation) · T-014 full training run to convergence (experiment, 3 seeds if
affordable) · T-015 multi-scale inference + optional per-patch optimization refinement · T-016 reproduction experiment and gap
analysis · T-017 M2 demo + gate review (final numbering: T-017 = loss ablations, T-018 = M2 demo + gate review).
VRAM estimate: PT is a small model (~10–15 M params); training on 32×32 patches with batch ≤ 64 in bf16 ≈ 2–4 GB; inference at
512² with K≈5 layers < 2 GB. Training time: to be measured (paper reports on their hardware; we train until validation loss plateaus).
Success criteria: (1) trained model converges (validation loss plateau documented, curves committed as small figures);
(2) inference produces a full painting at 512² with a stroke count of the same order as the paper; (3) every paper number we can
reproduce is reproduced or the gap is quantified and explained; (4) reproducible from one command per table; (5) demo GIF from
the PT pipeline via our animation module.

## What the study (T-010) measured against these estimates

| item | plan estimate | measured / found (source: [paint_transformer.md](../design/paint_transformer.md)) |
|------|---------------|------------------------------------|
| model size | ~10–15 M parameters | **9,072,902** trainable parameters (official PyTorch code, `Painter(5, 8, 256, 8, 3, 3)`) |
| training VRAM | 2–4 GB (bf16, batch <= 64) | **3.6 GB peak in fp32** at batch 64 on the official recipe (RTX 5070); bf16 would be lower |
| training time | to be measured | **0.237 s/step, 3.7 h** for the official recipe (56,320 steps, batch 64) on our GPU; the paper: 3.79 h on a 2080 Ti |
| inference VRAM at 512² | < 2 GB with K ≈ 5 layers | **2.3 GB** (official code, parallel mode, K = 4 + the shifted final layer); serial mode is lower |
| stroke count of the paper | "same order as the paper" | the paper **does not state one**; the released weights paint **3,787–4,991 strokes (mean 4,336)** at 512² on our five images (max 5,040) |
| validation | "validation loss plateau" | the official code has **no validation set**; one must be defined (held-out synthetic batches with a fixed seed) |

## Proposed refinements (for the chef to accept; none is applied silently)

1. **T-011** (rendering + data): besides the generator, add the *PT-compatible mode* of the renderer specified in section 1 of the study note: two brush images
   selected by `h > w` (no canonicalization), alpha modes `pt_infer` / `pt_train` (binarize + 3 x 3 erosion), foreground = 3 x 3 dilation of `gray * colour`, black canvas, no opacity.
   Decide the brush-asset policy first (the official PNGs are Apache-2.0 repository assets: fetch with checksums into `data/raw/`, not committed; or procedural look-alikes).
   The generator must follow the official `set_input` distribution (section 2): background canvases cut from 64 x 64, `x, y, w, h ~ U(0.2, 0.7)`, validity rule with the **0.75** threshold;
   its statistics are a test (official: 6.92 ± 0.91 valid strokes of 8 per patch, histogram in the study note).
2. **T-012** (model + losses): make the official architecture the target and test it numerically: parameter count **9,072,902**, and, when the official weights are present locally
   (`scripts/pt_reference_study.py fetch`), loading the official `state_dict` into our module must reproduce the official outputs for random inputs. Losses with flags for each documented
   paper/code discrepancy (matching cost `1 - logit` vs the lambda_r-weighted BCE; colour sampled vs predicted; loss weights). Default = the code (`pos_weight` 10, BCE weight 10, pixel weight 10, stroke L1 1, W 10);
   the **"paper loss weights" preset** is `pos_weight` (lambda_r) 8, BCE weight 1, pixel weight 1, stroke L1 1, W 10 with the BCE-based matching cost (study note section 4 and 9, [P Eq. 2, 11-13]).
3. **T-013** (training): schedule options matching the official one (56,320 steps x 64 = 3.60 M samples; Adam betas (0.5, 0.999); lr 1e-4 with the x0.3-every-5-epochs tail), a fixed-seed **synthetic validation set**,
   and a profile of the Hungarian matching (CPU `linear_sum_assignment` per sample is likely a large part of the 0.237 s step).
4. **T-014** (full runs): 3 seeds x ~3.7 h is affordable. Optional follow-up ticket **T-014b**: the four ablations of Table 1 (w/o `L_pixel`, `D_L1`, `D_W`, `D_bce`), ~4 x 3.7 h.
5. **T-015** (inference): reproduce the official procedure exactly (`K = ceil(log2(max/32))`, nearest resizing, four-phase window rendering, **shifted final layer**) and report both variants of the final layer
   (official: all 2,312 strokes painted; confidence-gated). Per-patch optimization refinement stays optional and reuses the M1 baseline.
6. **T-016** (reproduction): reproduce Table 1 (stroke part, ablations) and Table 2 (time ratios) as in the feasibility table of the study note; Table 1 real-image part only on our public-domain set with
   the official pretrained model as a reference row (documented in section 7); implement `L_pcpt` with a stated VGG layer. The paper-vs-code discrepancy list (section 9) is the starting point of the gap analysis.
7. **New (proposed) ticket T-018, eval protocol note:** pin down the `L_pcpt` definition and the synthesized-stroke protocol of Table 1 before T-016 (can be merged into T-016 if small).
8. **T-017** unchanged (demo GIF from the PT pipeline through `StrokeSequence` and the animation module; the adapter orders strokes by (layer, phase, stroke index, patch) as described in the study note).
9. **Success criterion (2)** should read "a stroke count in the range of the released model (3.8–5.0 k at 512²)", since the paper gives no number.
10. **Success criterion (3)** should list the reproducible items explicitly: T1b, T1c, T2a, T2b, Fig. 5/6/7 (see the feasibility table); T1a absolute numbers are not reproducible (datasets not available).
